## 失败项（原样）

无。7/7 全部 PASS；过程中未遇到任何 `ok:false`/`-320xx` 错误（唯一非 0 退出码是 `gui compare` 像素不匹配的预期 exit 1，属对照实验）。

## 帮助/skill 缺口

1. **世界帧的像素验证不可定位**：`gui screenshot` 没有 `--region`/裁剪选项，`gui compare` 的帮助只讲 GUI golden 与 `--channel-tolerance`。本实例在雪原下雪，任意两帧无编辑窗口截图也有 **91.4%** 像素不同（`differentRatio:0.914`，pairB vs pairC，均无箱子），全帧 diff 被雪粒/云/天空淹没，"截图与服务端摆放一致"只能退化成 pixelHash 变化 + `open-block` 成功这类间接证据。帮助应说明世界帧比较的动画噪声问题（或提供裁剪/区域比较）。
2. **未知命令组静默"成功"**：`mcdebug server --help` 打印**根**帮助且 **exit 0**——agent 无法察觉拼错/不存在的命令组（本例：根本没有 `server` 组，`server.runCommand` 只能靠 skill 文本发现）。应与其它 CLI 错误一致地 exit 1 并报 unknown command。
3. **`gui.status.jarPath` 为 `'/'`**：该字段的文档用途（发现 mods/ 里的陈旧 jar 副本）在此 NeoForge 客户端上完全不可用，帮助/skill 都没说它可能是 `'/'`。
4. **snapshot/trace 的 storage 字段语义**：同一 stack 按 handle 重复出现 skill 有提，但"清空槽位后 `capacity` 64→1、`amount`→0"这类字段联动**没有文档**——写"只有 item/count 变了"这类断言会误报。
5. **`trace get` 帧结构未文档化**：实际是 `{"tick":N,"snapshot":{…}}` 嵌套（快照同 schema），只能靠翻原始 JSON 发现；skill 只说"pipe it through a filter"。
6. **两平面坐标基准差异未说明**：`gui screen` 槽坐标是绝对 GUI 单位（slot0=(133,54)），`screen.*` 的 `slotDetails` x/y 是容器相对（slot0=(8,18)）；帮助没讲两者的偏移关系，"同一界面两种视图"的比对要自己推断。

## 未能判定

1. 无雪/无动画场景下，窗口截图的像素差异能否定位到箱子区域（需好天气重试或裁剪功能；本环境噪声地板 91%）。
2. 快照 storage 里空槽 `capacity` 变 1 的语义（NeoForge 按 handle 状态推导的近似值？需源码或 Fabric 侧对照）。
3. `jarPath:'/'` 是 NeoForge 打包固有行为还是 bug（需另一实例/源码）。
4. 客户端日志 t8553 两条 WARN（`Server attempted to add player prior to sending player info` / `Skipping Entity with id entity.minecraft.player`）时间上疑似由 `screen open-block` 的服务端假玩家进入真实客户端视野触发（无害，实体被跳过）；确认因果需要在调用前后用 `gui problems --since` 游标做对照。
5. 实例启动 WARN `mcdebug RPC failed to bind TCP port 25580: Address already in use — continuing without it`：与本批次无交互，符合"单边绑定失败只 WARN"的文档行为，推测同机另一实例占了 25580。
