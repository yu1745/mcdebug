## 失败项（原样）

### F1 任务 7 — `gui.hover` 拿不到 tooltip，且 hoveredSlot 与 gui.screen 槽位相互矛盾
命令（干净复现，玩家存活、无死亡屏干扰）:
```
mcdebug --socket .../run/mcdebug/socket raw server.runCommand '{"command":"give @p minecraft:emerald 3"}'
mcdebug gui open-screen inventory
mcdebug gui screen                 # → items: [(36,'minecraft:emerald',3)]（槽 36 = 热键栏 0，gui (133,179)）
mcdebug gui hover --slot 36 --shot window --draw-log
```
响应（关键字段）:
```json
{"mode":"slot","guiX":141.0,"guiY":187.0,"via":"slot=36","slot":36,"ok":true,"cursorMoved":true,
 "tooltips":[],"hoveredSlot":13,"stack":{"item":null,"count":0},"reason":"EMPTY_SLOT","screen":"container"}
```
- 光标落点正确（141,187 = gui.screen 给的槽 36 中心），但 `hoveredSlot` 报 13（与 gui.screen 的 slots[].index 体系不一致；此前 `--gui 159,187`（另一位置）也报 13），`stack` 空、`reason:"EMPTY_SLOT"`——服务端 `data get entity Dev Inventory` 与 gui.screen 都确认该槽有 emerald x3。
- 同一往返的 `--draw-log`：该帧 ops `{blit:59,text:12,item:4,fill:4}`，**没有 `tooltip` op**，texts 里也没有物品名（只有 'Crafting'、药水 HUD、教程 toast）→ tooltip 实际没被画出来，不只是采集失败。
- 非容器控件同样为空：VideoSettings 选项按钮 `hover --gui 133,97` → `tooltips:[]`；Options 难度锁图标 `hover --gui 357,39` → `tooltips:[]` 且 `hoveredWidget:null`。
期望: 帮助承诺 "tooltips - every tooltip drawn in that frame" 与 `hoveredSlot`/`stack` 反映真实槽位（物品槽必有 tooltip）。
影响: 可绕过但不可替代——点击路径（click --slot/--text/--widget/--gui/--png）全部正常，像素/控件/输入闭环不受影响；但"读 tooltip 做断言"的工作流在 NeoForge 客户端上不可用。怀疑点（需源码判定）：hover 强制帧的鼠标位置未真正生效（hoveredSlot 由旧位置算出），或 NeoForge 侧 tooltip 采集 mixin 未命中。

### F2 任务 3（crop 子项）— 截图裁剪参数静默失效
命令:
```
mcdebug raw gui.screenshot '{"mode":"window","crop":[0,0,427,240]}'      # 另试 [100,100,300,200]、{"x":..,"y":..,"w":..,"h":..}、"region":[...]
mcdebug gui screenshot --crop 0,0,100,100
```
响应:
- raw 全部 200 OK：`format:"png"`、`transform.crop:[0,0,854,480]`、`pngSize:[854,480]` —— 请求的裁剪被**静默忽略**，返回整窗图（未知参数不报 -32602）。
- CLI：exit 1 `Error: no such option --crop`（CLI 层没有裁剪旗标）。
期望: 要么按 crop 裁剪，要么 -32602 报参数名；TASKS 以 `--crop` 出题说明该能力应存在。
影响: 可绕过（`--mode gui` 能裁容器矩形；`--out` 后本地裁剪）；但"静默成功 + 错图"对回归流程是危险语义。

## 帮助/skill 缺口

1. **`gui.screenshot` 的 RPC 参数面完全未文档化，且未知参数静默忽略**（F2 根因）：CLI 帮助只列旗标（`--mode/--annotate/--draw-log/--hash-only/--hide-cursor`），raw 层的 `crop/format/cursor` 名字没有任何一处写明；传错名（或传对名但形状错）不报错，直接按默认出图。skill 的 compare 一节提过 "format:none / cursor:hide" 但 screenshot 一节没有参数表。
2. **hover 返回值中 `hoveredSlot` 的编号体系未说明**（F1 陪衬）：它显然不是 gui.screen 的 `slots[].index`（36↔13），帮助只说 "the container slot under the cursor"；两套编号并存且没有换算说明， agent 无法自查 hover 是否落在预期槽上。
3. **drag 报告不回显起点**：结果只有终点 `guiX/guiY` 与 `space/button/steps`，`--from` 不在响应里；帮助也没有 drag 的"What comes back"一节（click 有）。
4. **CLI 旗标与 raw 参数名的映射没有说明**：`--hash-only`↔`format:"none"`、`--hide-cursor`↔`cursor:"hide"`、`--mode gui`↔容器裁剪，全靠试；黑盒视角两者像两套 API。
5. **`gui open-screen` 的可开类名无从发现**：`net.minecraft.client.gui.screens.controls.ControlsScreen`/`KeyBindsScreen` 均 `CLASS_NOT_FOUND`（1.21.1 真名不同），错误只提示 "(runtime/Mojang name)"，没有任何列出/搜索 Screen 类的办法；`inventory` 这个别名只写在帮助例子里，全量别名表不存在。
6. **reflect 取"类名"没有可用路径**：`--path class.name` 与 `getClass().getName()` 都 -32602（Object 继承的方法不可走），实际正解是 `reflect resolve`；`reflect get --help` 未提示这一限制。
7. **compare 失配时输出不是纯 JSON**：mismatch 时 stdout = 一行 JSON + 一行人类可读 `error: Screenshot com...`，`json.load(整个stdout)` 会炸；且 JSON 行与 error 行的关系未文档化。`--diff` 在尺寸不匹配时不写文件（帮助有写，但藏在 bullet 里）。
8. **无屏时 `gui key/type` 的错误码复用 -32020 CLIENT_NOT_READY**：消息清楚（"no Screen is open"），但 data.reason=CLIENT_NOT_READY 与"客户端没起来/没进世界"同码，按 reason 分流的自动化会误判。
9. **`gui.status` 的 `jarPath:"/"` 无解释**：brief 显示 `jar: /`，发布 jar 路径显然没取到；没有任何文档说明这代表什么（NeoForge 打包态？）。
10. **hotswap `attached:false` 语义与 skill 相左**：skill 说 `attached:false` = agent 早已加载；本次首次调用且 changed:0 时也返回 false（疑似"没事可换就不 attach"），该分支未文档化。
11. （小）`gui click --gui/--png` 结果缺 `via`/`before`（--widget/--text/--slot 都有），帮助的"What comes back"未区分目标类型。

## 未能判定（需维护者用源码/另一实例）

- F1 hover/tooltip 失效的层级：是鼠标位置没生效（hoveredSlot 按旧位置算）、NeoForge tooltip mixin 未命中，还是该 MC 版本本身不画这些 tooltip —— 需对照 Fabric 实例或源码。同一实例上 `click --slot` 的槽位解析是正确的，说明几何/槽位数据本身没坏。
- F2 crop：0.7.0 是否曾实现过 `crop` 参数（还是从未有）；若实现，正确的参数名/形状是什么。
- 环境事件（非工具故障，但影响会话稳定性）：会话期间玩家**自行死亡 2 次**（死亡时我在做 GUI 读取，命令序列无任何伤害来源），`gui status` 正确显示 DeathScreen、`gui click --text Respawn` 正常复活；玩家坐标还在无人输入下漂移（z: -77 → -199）。为稳定测试，我用服务端平面给了 `resistance 255` + `fire_resistance`（各 1000000s ≈ 277h，ambient）——**如后续批次需要可受伤的玩家，请 `effect clear Dev`**。另：两次死亡掉落的物品实体已 `kill @e[type=item,distance=..48]` 清掉（4 个）；Biome Blend 已还原 5x5 (Normal)；背包已清空；recipe book 已关闭；结束时状态 = 世界内、无屏幕。
- 启动噪声 `mcdebug RPC failed to bind TCP port 25580: Address already in use`：与本实例无关（服务端平面 tcpPort:-1，socket 正常），疑似同机另一实例占用，仅记录。
