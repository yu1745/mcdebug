# 平台语义与闭环验收清单

按当前行为涉及的边界选取，不机械要求每轮跑全量。每个结论关联源码位置和运行证据；编译、启动、注册、实际调用是不同层次的证据。

## 1. 适配前核对语义

| 边界 | 必须查清 | 最小有价值的验证 |
|---|---|---|
| 注册与生命周期 | 静态初始化、事件时机、注册冻结、客户端/服务端隔离 | 干净启动并实际创建/使用对象；专用服无客户端类加载错误 |
| capability → lookup | owner、side/context、暴露条件、缓存失效、区块卸载 | 同一侧允许→禁止→允许；破坏/重放或卸载后旧引用不误用 |
| 物品 | 空栈、组件、槽位限制、可变栈引用、插入/提取规则 | 合并、拒绝、满槽、方向性；转移前后总量守恒 |
| 流体/能量 | 领域单位与平台单位、精度、溢出、容量、每 tick 速率 | 小量/非整单位、满/空、部分接收；无重复或损失 |
| simulate / execute / transaction | 嵌套事务、提交/回滚、变更通知与保存副作用 | 模拟不改变状态，abort 恢复状态，提交只生效一次 |
| 网络与 menu | 编解码顺序、方向、线程、增量/完整同步、初始数据 | 打开→操作→服务端读回→客户端确认→关闭重开 |
| NBT / item components / codec | 类型宽度、默认值、缺字段行为、注册表上下文 | 实际行为验证后保存、重启、读回；不只做 JSON 自身往返 |
| 配方与数据 | 注册 ID、标签、条件、数据生成、资源加载顺序 | 真实输入在允许条件下产出；错误输入不执行 |
| 配置 | 加载/重载时机、服务端权威、作用范围 | 修改测试配置后验证实际行为，不仅检查文件被解析 |
| 渲染 | 模型烘焙、材质/atlas、UV、着色、渲染层、变换与裁剪 | 实际对象/界面出帧并读图；注册日志不能替代绘制验证 |

不要将所有 simulate 简单映射为“先改再改回”：监听、同步包或保存副作用可能已经不可逆。也不要用“目标先插入、来源再提取”的两个独立调用冒充原子转移。事务契约必须在 adapter 与真实 owner 的连接处成立。

## 2. 跨加载器对照规则

原版参考端也是被观察对象，不是可以随意修改到“与目标一致”的基线。对两端施加相同语义输入，保留原始结果，再做明确的归一化。

- 记录源码 commit、jar 哈希、MC/加载器/工具版本、配置、存档夹具、会话身份与操作顺序。
- 读取 `server.status` 的 `fluidUnit`/`energyUnit`，不要根据字段名猜单位。工具当前默认流体单位为 Fabric droplet（81000/桶）、NeoForge mb（1000/桶）；领域模型内部单位可能另有定义，转换只在边界进行。
- `E`/`FE` 标签不证明领域能量等价，需以目标 API 与上游算法确定换算和舍入。
- NeoForge 流体的 index 可能只选择报告的罐，实际注入/抽出仍由 handler 路由；不能把它当成指定罐写入。
- `supportsInsertion/Extraction` 可能分别表达能力或当前可操作状态；比较实际可执行行为，不机械比较布尔值。
- 剔除经过说明的非语义字段，例如实例 ID、时间戳、绝对路径；不要把所有不同字段都加入忽略表。
- 不默认二进制网络协议互通，也不默认开发中间版本存档可互换。对上游存档兼容的承诺需要单独离线副本验证。

差分分类：

```text
PASS       同一语义行为一致
EXPECTED   已说明依据并获允许的平台差异
FIXTURE    输入、配置、时序或存档不等价；修夹具后重跑
DEFECT     移植实现偏离原行为
BLOCKED    工具/环境无法观察；不能据此声称通过
```

### 可选：NeoForge 存档 → Fabric 加载

用于验证已有机器存档的互操作性。启用此项时，**服务端 API 操作/读回与截图视觉辨认都要执行**。

1. 在隔离 NeoForge 世界中真实摆放代表性机器，用服务端 API 准备输入、燃料或能源并触发工作，读回机器 ID、方块实体、库存、资源量和设置；截图并亲自辨认机器布局、朝向、连接及 GUI，记录坐标和观察结果。保留待加工输入等状态，供迁移后续用验证。
2. 正常保存并停止 NeoForge，离线复制完整存档到同 MC 版本的 Fabric 测试环境；原存档保持不动，玩家相关验证使用同一 UUID。
3. Fabric 加载副本后，先用服务端 API 检查原位置的机器、库存、资源和设置，再实际操作这些已有机器，确认能继续加工、取出或搬运且数量守恒。检查加载日志中的缺失注册项、解码错误及数据丢失，不用重新放置机器代替旧存档加载验证。
4. 在 Fabric 的对应位置和视角截图，亲自从画面辨认原机器及其布局、朝向、贴图、连接，再打开 GUI 检查槽位、文字与工作进度。与 NeoForge 截图和服务端读回交叉核对；只查坐标/NBT或只生成图片都不算完成。

保存两端原始响应、截图、加载日志及版本身份，结论注明迁移方向、测试范围和发现的差异。

## 3. 状态、交互与视觉证据

一条端到端验收至少回答：

1. **操作前：** 初始资源、方块状态和菜单是什么？是否读回确认？
2. **操作：** 真实用户路径是什么？点击/使用是否真的改变了目标？
3. **服务端：** 预期状态变化和守恒关系是否成立？验证拒绝/停止边界时，其它执行前提在观察期间是否仍满足？
4. **客户端：** settle 后 menu、标签、进度和 tooltip 是否同步？
5. **截图：** agent 实际看到了什么，是否与源码/参考端预期一致？
6. **重启：** 需要保存的状态是否保留，是否还依赖调试注入？

命令退出 0 不等于业务成功。检查 JSON 的 `ok`、`changed`、`settled`、`reason`、实际插入/转移数量与读回值。`gui act` 的动作、截图和 screen 可能分别失败，保存完整结果，不丢掉其中的错误。

验证玩家库存或 attachment 的保存重启时，固定并读回两次运行的玩家 UUID；开发启动器可能每次生成不同默认用户名。先排除身份变化、死亡和未正常保存造成的夹具差异，再判断持久化缺陷。

`inv.setSlot`/NBT/反射写入只证明夹具建立，不能证明玩家槽位规则；`world.setBlock` 不一定执行物品放置逻辑；直接打开 Screen 的工厂夹具不能证明玩家右键路径。明确区分单层探测与最终用户路径验收。

## 4. 截图比较不替代理解

稳定 UI 可使用：

```bash
mdb --session port-target gui screenshot --mode gui --hide-cursor --out /abs/evidence/actual.png
mdb gui compare --expected /abs/evidence/expected.png --actual /abs/evidence/actual.png \
  --report /abs/evidence/compare.html
```

- 统一实际窗口尺寸、GUI scale、语言、资源包、背景和状态；记录渲染后端。跨 GPU 不承诺像素确定性。
- 标注图用于定位，干净主图用于比较；tooltip 用 hover 单独验，hide-cursor 会隐藏它。
- 只对已知动画/背景噪声设置有限 ignore 区域或通道容差，不能遮掉正在验证的控件/进度条。
- 尺寸不符直接调查，不能缩放图片掩盖布局缺陷。
- 世界画面含时间、天气、实体动画，优先状态断言与人工读图；hash 变化只说明像素改变。
- golden 必须有可信来源；目标端第一次生成的画面不是天然正确。不得自动 `--accept` 消除回归失败。

## 5. 运行与发布门禁

日常循环按受影响面验证；功能里程碑再执行仓库要求的完整门禁：

- 专用服务器与客户端分别启动，排查侧隔离、注册、mixin、网络和资源故障。
- 用最终 jar 在没有目标项目 dev classes 的独立消费者中运行，检查入口点、内嵌依赖、生成资源和重映射；直接检查工件内应随附的 LICENSE/NOTICE 等许可文件，内嵌依赖也须保留其许可，不能仅确认源码根有文件。
- 消费者的 Gradle `runClient` 可纳入 mdb session 管理；记录它是否重映射 jar。只有开发消费者的结果时，不宣称已经验证未经重映射的生产客户端。
- 检查调试工具、临时夹具/工厂、参考源码和测试数据没有进入发布依赖或产物。
- 任何跳过的构建、服务端、客户端、持久化或发布物验证必须列明，不能用另一层成功覆盖。
