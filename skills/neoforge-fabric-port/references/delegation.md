# 强弱模型协作：主代理规划与审查，worker 执行

这是角色分配协议，不依赖某个厂商、模型名称或子代理工具。主代理使用适合源码推理、平台语义判断和审查的强模型；worker 使用成本较低、能执行有界编码和工具操作的模型。真正的成本目标是**每个验收通过切片的总成本**，不是单次调用最便宜。

## 1. 主代理先产出 roadmap

主代理先读本 skill、仓库约束、上游源码及已有移植状态，再写项目内持久化 roadmap（沿用现有位置，不另造重复状态系统）。可让 worker 收集限定范围的文件清单或编译错误，但行为 owner、适配方案及验收标准由主代理核实。

roadmap 至少包含：

```text
目标与固定基线：源/目标 commit、MC/加载器/API/映射版本
允许修改范围、兼容性承诺、非目标
必须保持的领域语义与已允许的平台差异
现有能力与阻塞：构建、启动、服务端、客户端、发布物

切片 ID | 用户行为 | 真实 owner | 前置切片 | 平台适配路线
        | 不变量 | 验收命令/场景 | 证据要求 | 状态

当前可执行切片、选择原因、待裁决问题
```

- 先接一条完整用户路径，再扩展同类能力；不把“改完所有 import”当里程碑。
- 详细展开当前切片及直接前置，后续切片只保留边界与依赖，避免对未知代码过度规划。
- 状态建议：待规划 → 可派发 → 执行中 → 待审查 → 需修改 / 阻塞 / 已验收。
- worker 可报告方案与估计，不直接修改权威 roadmap 的范围、允许差异或完成状态；由主代理裁决并更新。

## 2. 派发的是完整任务契约

任务单必须自包含，文件路径用绝对路径或明确的仓库根相对路径。不要依赖子代理自动加载父会话的 AGENTS.md，也不要让它从海量对话里猜当前要求。

```text
角色：你是执行 worker，不负责重定 roadmap 或最终验收。
任务 ID / 基线：
工作目录 / worktree / 源码 commit / 干净程度及已有用户改动：
必读：本 skill、对应参考文档、适用仓库约束（附关键条款）、指定源码位置。

目标：接通哪一个可操作的用户行为。
上游依据：owner、关键调用链、原行为和平台差异。
已定路线：复用哪些实现、adapter 放在哪个边界、禁止哪些替代方案。
不变量：ID、领域算法、单位、事务、线程、同步、保存语义等适用项。
允许修改：精确目录/模块；共享接线的唯一负责人。
非目标：不扩展哪些模块，不引入哪些兼容/迁移承诺。

执行：修改→最小构建→确认代码生效→mdb 操作→状态读回→截图观察→修正。
验证：实际任务名、夹具、输入、预期输出、边界用例、重启/发布物门禁。
环境：四类参考源码的精确路径/版本/映射/生成元数据；专属 session、显式 sessions-dir（registry/启动日志）、gameDir、存档副本、证据目录、参考端与资源预算。
权限：是否可写源码、运行游戏、创建本地提交；无授权不得部署、push 或操作生产。
搜索：仅在列出的源码目录用 rg/fd，限定深度/文件模式；不扫描根目录。
      必须排除 ~/server、/backup、~/win 及其子目录；超时/卡住即停并缩小范围。
安全：不改参考源码、原始存档和他人改动；不删锁，不杀共享 daemon。

停止并上报：新语义决策、越界依赖、数据损失风险、缺环境/基线，
            或连续两轮同一失败无新证据；带原始错误、尝试和最小复现。
交付：准确 diff/commit、变更解释、可重放命令、原始结果/日志/截图路径、
      已观察结论、未跑项、阻塞及 session/进程清理状态。结论只能是“待审查”。
```

约束透传不限于文件名：把会影响本轮行动的关键规则写进 prompt；长文档可给精确路径供读取。需要新的范围或语义时，worker 只提建议，不默默决定。

纵向切片跨多个平台 owner、一次执行难以收敛时，保留完整切片作为最终契约，每次派发只展开一个 owner 的闭包：定义、真实接线点、直接调用方和本轮证据。提供最终契约的路径供查阅，明确本轮结束条件，避免让 worker 每轮重新承担整个移植。闭包不是只新增未接线 helper，也不要求把无关 owner 一并修完。

工程尚不可编译时，记录本轮 owner 的实际变化及剩余首因；全工程错误可能遮蔽类型错误，“日志未报该文件”不能证明它已通过。相关闭包集成后仍须完整构建和纵向游戏验收。

## 3. worker 执行闭环，不只提交代码

worker 对已定路线拥有范围内的实现和调试空间，不必每改一行都问主代理；但不能自行改不变量或验收标准。

执行修改、构建、生效确认、真实交互、读回、读图、修正与重放，沿用主 skill 第 5 节的闭环。任务单可缩小本轮 owner 闭包，不能改变最终用户路径和发布物门禁。

每项关键观察及时保存原始响应、截图及对应会话/产物身份；worker 亲自读图，交付后由主代理独立复核。返回准确 diff、可重放命令、未跑项和阻塞，结论只到“待审查”。结束时正常停止 owned 会话；若明确交给主代理复现，交接 session、存档与当前状态，不能留下无主进程。

## 4. 主代理写可执行的审查意见

审查对象是**实际 diff + 上游依据 + 原始运行证据**，不是 worker 的自述。记录审查的 commit/diff 基线，worker 修改后旧审查不能自动覆盖新版本。

至少检查：

- 行为是否仍由正确 owner 承担，是否出现重复框架、no-op 或绕开必要源码的假绿。
- 平台差异是否按契约处理，尤其事务、单位、线程、注册时序、网络及持久化。
- 实际启动的是否为新代码，夹具是否绕过被测行为，命令是否业务成功。
- 亲自打开关键截图，结合 menu/服务端状态检查；不能只看“截图已生成”。
- 相关日志、回归和重启证据是否支持完成声明；缺失证据明确标出。
- 按风险重放关键路径；跨切片接线、资源守恒和保存类改动不能只靠单 worker 自验。

对 diff 中被删除或改签名的平台 override、事件订阅和扩展接口，逐项核对：`上游入口 → 原调用方/适用范围 → 目标等效入口 → 证据或未关闭项`。不能只看替代方法仍存在；自家代码主动调用一个 helper，不代表原版或其它模组也会调用它。没有目标调用方的同名方法、只覆盖自家机器的特判，都不能据此认定全局行为已保留。

配置若参与注册、构造或状态缓存，查实际读取与缓存时机，确认加载顺序；配置文件写入成功或运行后读值正确，不足以证明已构造对象使用了该值。为这些差异选择受影响的最小验证，不无限扩大整模组验收矩阵。

每条意见采用：

```text
R-ID / 级别：阻断正确性 | 缺必要证据 | 非阻断建议
位置：文件:行 / 行为 owner / 证据路径
依据：对应上游行为或已定契约
发现：实际偏差，以及什么输入会触发
修正方向：最小行为边界内应改变什么（不只写“优化一下”）
验收：复现步骤、应观察的结果、需重跑的回归
```

结论是“通过 / 需修改 / 阻塞”，不要把个人风格偏好包装成正确性阻断。新增需求回到 roadmap，不借审查无限扩张当前任务。

worker 按 R-ID 修复并逐条回报；主代理复读新 diff 和证据，确认没有引入相邻回归后关闭意见。worker 不能自行关闭主代理的阻断意见。

## 5. 并行、集成与升级

- **默认一个写入 worker。** 多 worker 只用于依赖已满足、行为和文件边界真正独立的切片；只读调研可并行。
- 并行写入使用独立 worktree/分支、构建输出、gameDir、存档、session 与证据目录；也要检查端口和 CPU/内存预算。不能并发控制同一个 GUI 或重启彼此实例。
- 共享注册、网络协议、构建配置和公共 adapter 指定唯一写入者；其他 worker 返回接线需求，不争抢文件。
- 主代理按依赖顺序集成，可指派单一 worker 执行受控集成；不覆盖用户改动，不以文本合并成功代替语义验证。集成后重跑受影响行为，再标记已验收。
- worker 连续失败无新证据时，主代理先诊断任务是否过宽、上下文是否缺失、路线是否错误。补源码依据、拆成仍可验收的闭包或重新设计，不无限堆尝试次数。
- 若连续更新只有“等待”而没有实际进展，主代理核实最后成功动作、当前工具调用或错误、进程/session及可用端点，再定下一条可执行动作；正常长任务不因安静而反复打断。
- 必须强推理的难点由主代理调查并形成明确决策后交回 worker；若确需强模型直接实现，记录例外及原因，完成后仍审查真实 diff 并验收。
- 子代理不可用、模型不可选或仓库禁止写入型子代理时如实说明，采用串行阶段或允许的只读协助；不能假装已经实施强弱模型分工。

## 6. 主代理检查点

每轮审查后持久化：roadmap 状态、基线/集成 commit、仍未关闭的 R-ID、证据路径、当前运行会话和下一条任务。新上下文只凭这些文件应能恢复工作，不依赖 worker 的临时记忆。

最终向用户报告由主代理负责：哪些行为已验收、哪些只有编译/启动证据、剩余阻塞和下一步。weak worker 的数量或完成报告不构成模组完成度。
